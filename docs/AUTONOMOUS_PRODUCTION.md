# 0.3.3 系统自主返修与制作验收

本版本把预算内的局部返修交给现有 worker：读取独立审核诊断，保存定向返修计划，将批准事实写入实际生成请求，审核新产物，然后继续制作或停止并说明原因。无需出品人逐个点击重复生成。终稿仍等待人工验收，对外发布仍需单独授权。

工程测试验证执行协议与停止边界；不代表真实模型生成质量已改善，也不代表两集成片已交付或用户验收通过。本版本目前仍待用户实测。

## 启用与历史项目

新授权的连续制作使用 `ai-studio.production-recovery.v2` 执行策略；历史 v1 保留原行为和原尝试上限。读取、刷新或打开历史项目不会自动改写其配置。

已有连续制作项目可在全剧暂停后点击“启用自主返修”（v1 项目显示“升级自主返修”）。业务请求为：

```http
POST /api/factory/dramas/{id}/actions
```

```json
{
  "action": "enable_autonomous_repair",
  "request_id": "apply-recovery-unique-request",
  "expected_revision": 12
}
```

`expected_revision` 使用最新项目修订号，`request_id` 使用本次操作的唯一幂等编号。不要传入预算、模型或镜头变更。服务端要求全剧暂停、连续制作授权挂起，且相关任务到达安全边界；未知远端请求必须先对账，不能借升级重投。

策略只应用于已授权、尚未完成的剧集与制作单元，并记录执行快照变更。已批准素材、历史计划、费用、预算和尝试次数保持原样。未进入授权范围的剧集及已交付单元不被重制。成功响应后仍保持暂停；用户明确点击“继续制作”才释放执行。

页面显示“自主返修已启用”以服务端返回的策略为依据。正在提交时按钮禁用；未暂停的项目不显示升级按钮，v2 项目不重复显示该入口。暂停请求仍在收尾时，服务端会拒绝提前应用策略；按钮出现本身不是远端任务已经完成的证据。配置或预算变化继续遵守原有明确授权流程。

## Worker 如何处理失败

1. 首次生成沿用批准分镜、真实参考、冻结模型配置与已有配音。
2. 独立审核明确判失败后，执行器检查剩余次数与预算，保存与具体素材、批准事实和旧失败版本绑定的诊断与岗位交接。
3. 需要首帧证据时，视觉岗位读取真实像素；缺少审核时先补审原图，确有冲突时交回图像岗位修复。新首帧必须独立审核通过，再进入视频制作；其他已通过素材继续复用。
4. 分镜导演实际调用冻结配置中的模型，生成不同的可见动作方案。方案经过批准事实、起始状态和适配器参数验证，编译成生成岗位实际提交的请求。审核失败文字不是生成提示词，计划登记本身不算完成返修。
5. 新产物重新接受技术与独立语义审核，通过后才进入选片与后续制作。交接文件记录当前岗位、实际请求、媒体哈希与复验结果；暂停后复用已完成的工作。

视频的明确运镜要求单独核对：观察员只接收候选实际抽帧、时间戳和运动类型定义，不接收批准运镜、剧情节拍、参考图或旧分数；代码将观察结果与原 `camera_motion` 比较。清晰的不同运动会阻断高分通过，混合运动、证据不足或像素变化保留素材待补审。`camera-observation/evidence.json` 记录媒体哈希、样本编号、观察结果和核对结论。这仍是抽帧模型观察，不能代替人工审片。

初次生成和定向返修均把批准运镜枚举翻译为可见运动描述，例如向右平移对应固定背景在画面中向左移动；“剧情推进”不能变成相机前推。所有可见人物（包括背景人物）仍须符合本镜身份与关系，首帧参考本身不授予添加人物的权限。

v2 明确登记至多两次不同方案的附加尝试，原三次普通尝试可加至五次；同一对象最多两轮有效策略、每单元最多八轮。GPU 分钟、执行时限与原费用不变，普通尝试记录仍保留。此额度仅在显式启用或升级 v2 时授予，重复升级、继续或重启不会重新发放；v1 不会因读取新代码而获得附加次数。换首帧后保留来源谱系计数，不通过新来源清零。

执行模型调用前写入持久意图，返回后保存实际结果；生成任务提交与产物回执也独立保存。只有尚未提交的准备记录可以原样恢复，结果未知时先停止对账，不盲目重投。

已知的临时审核连接故障最多后台延期两次，计数跨重启保留。恢复只复审原路径、原 take 和原文件，补审完成前不新增生成。没有明确结论、能力不支持、配置错误、未知费用、预算或次数耗尽时，系统保留成果并给出停止原因。单元、剧集和全剧状态由 worker 同步，刷新页面只读取状态。

## 原图复用与独立证据

组合参考图的像素、实体映射、版本、批准事实和实际制作规格相同时，刷新审核分数、审核签名或证据 manifest 不会触发下游图像重新编译、重画。生成身份与审核证据分开保存；必要的独立复核仍读取原文件。

真实像素、映射、版本、manifest 要求或规格变化会使缓存失效。manifest 缺失、校验不符或像素归属不符时停止，不能猜测或伪造兼容。旧批准计划、失败 take、费用及审核历史不被删除。

视频后段动作失败不自动否定已通过的首帧。系统可保留首帧并补强视频起始、中间与结束状态；需要上游修改的材料应明确路由，而不能偷偷换图后沿用旧观察。

明确要求人物闭口时，独立可见状态检查逐个检查实际带时间戳的抽样帧。任一样本明确张嘴会形成阻断诊断，不能被整片高分覆盖；看不清、缺失或重复样本则保持证据待定，不能自动判通过或据此重画。这是抽样证据，不是对视频每一帧的穷尽认证。

## 预算、远端任务和当前验收范围

预算仍按制作单元计量，GPU 用量与旧回执累计；计划返修本身不清零费用。总授权额会随长集拆分展示，不应将单元上限误当整剧总额。

当前自主返修策略覆盖既有 GPU 时间授权的本地模型链。按金额付费的供应商返修尚缺少可验证的货币授权边界，会明确停止，不能用 GPU 分钟授权代替新增付费许可。

本次代表性验证保持两集、每集120秒，后续原生视频采用352×640预览规格。仅首个制作单元得到200 GPU分钟授权，其他单元仍为120；这不是全局默认值，也不代表有权继续提高上限。高清首帧、已有配音与统一交付规格保留；放大的预览不应称为原生高清效果。

驻留 ComfyUI 的预算停止只针对本系统持有的 `prompt_id`。需先配置并验证 `owned_cancel_protocol: comfyui.jobs.cancel.v1` 和受支持的 `verified_comfyui_version`，运行时还会检查实际服务版本与任务接口。执行器使用 `/api/jobs/{prompt_id}/cancel` 的按任务原子取消协议，不用全局 interrupt，不取消其他项目。协议未核验时不提交新生成；取消或费用状态不确定时保留账本，停止新增付费请求。

已经运行的驻留模型与冷启动安装分别预检：驻留链检查实际节点接口、必需输入、模型选项与取消协议，并保留节点合同摘要；冷启动文件缺失仍单独展示。节点合同可用不等于已经通过真实生成质量验证，测试推理服务也不因此更新生产模型进程。

## 等待共享制作资源

其他任务占用模型或 GPU 时，可显式授权 `wait_for_resources`，请求只接受 `action`、`request_id` 和 `expected_revision`。此操作需要已有连续制作授权、当前任务已到安全边界且没有未知远端提交；不授予新的预算、模型或供应商配置。

worker 在原持久任务上每五分钟只读检查冻结模型目录和已驻留的生成服务能力。它不启动、停止、更换或预热模型，不提交推理或生成，不处理可能调用模型的团队指令。等待按执行暂停处理，单独累计资源排队时长，不消耗剩余 GPU 分钟或活跃制作时限；原上限、累计制作费用与尝试记录不变。

资源恢复后，同一任务自动接续原工作；暂停、取消、租约和配置版本检查优先。鉴权或配置损坏会明确停止，不能伪装为无限等待。页面显示“等待制作资源”，不把排队显示为正在生成，也不要求用户反复点击继续。资源检查只证明服务与配置可用，成片质量仍须由真实媒体审核及用户验收确认。

## 验收步骤与证据边界

1. 暂停一个已有授权的历史项目：确认升级前未隐式启用策略；点击“启用自主返修”（v1 项目显示“升级自主返修”）后检查只有执行快照和授权记录变化，项目仍暂停，预算、费用和成功素材不变。
2. 点击“继续制作”：确认后台 worker 接管制作；发生有依据的局部失败时显示定向返修状态，返修记录关联真实媒体版本、批准事实、提示词及下一次尝试。
3. 检查旧有效图像与声音复用；刷新组合图审核证据不会重画其他镜头，真实参考变化仍阻止错误复用。
4. 对带明确闭口及运镜约束的视频检查实际帧与时间戳；确认张嘴或错误运镜能阻止高分漏审，剧情节拍不会覆盖相机要求，不确定证据不会直接触发重画。
5. 在独立 fixtures 中验证重复恢复、未知请求、尝试上限、预算边界与按任务取消；确认其他任务和已完成媒体不受影响。
6. 最终分别播放两集，核对每集120秒、故事与对白、人物道具连续性、真实动作、声音、整片观感及实际费用。生成文件存在或自动测试通过均不能替代用户实测。

UI 测试验证按钮条件、忙碌状态和请求参数；Python fixtures 验证缓存身份、返修执行、审核证据及恢复协议。它们均不调用真实模型，不能证明画面、动作或声音效果。真实模型验证需使用已授权的代表项目，在预算内运行并保留成功、失败及退步样本；当前用户验收尚未通过。
