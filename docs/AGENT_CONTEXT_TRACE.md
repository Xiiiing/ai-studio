# 角色输入来源与版本追踪

本页对应 Agent 协作优化第一阶段（#58），不改变已有生产图、人工批准或模型分工。

## 查看本次材料

进入项目的制作工作流 → 部门协作 → 岗位 → 执行记录，展开“本次收到的材料”。普通步骤的执行记录也提供相同入口。

清单列出实际角色输入字段、内容摘要、原值 SHA-256、字节数及材料自身携带的版本；当次项目快照版本单独显示，不用最新项目版本替旧稿标号。用户反馈中的分层修改意见逐条记录。当前项目材料未能完整同值匹配时，显示“未确认”，不能据此推断角色已读取或资料缺失；摘要、摘录与改写可能不相等。

“窗口检查”来自实际 provider 的 tokenizer 或保守估算，保留输出预留。必需材料超限时阻止本次生成提交，提示拆分任务、减少可选参考或选择更大窗口。此阶段不增加自动裁剪；调用方原本明确标记的摘录会标明。展示摘要和清单条数限制只影响页面，不修改实际模型输入。

## 回执与复用

每次请求前保存 `context-NN.json`，包含输入清单、当次请求哈希与预算；`receipt.json` 记录未提交、尝试提交或取得响应。请求中出现某项材料不证明模型理解、落实或通过审核。多模态清单对实际文本及图像内容计算哈希，不在轮询响应中复制图像。

缓存仍使用既有精确输入、提示词、模型及输出约束的签名。新增缓存记录原始调用身份；复用写入单独观察记录，不生成新的模型调用、不修改原始缓存。复用原始输入仅在调用 ID、角色、提示词/输入/输出约束哈希及输出哈希一致时展示；缺少或不匹配时保持来源未知。记录复用证据失败也不能转成一次新模型调用。

整剧规划、单集创作、分镜及审核通过通用调用边界记录；H3 编译的独立缓存也保存来源和复用观察。旧回执、旧缓存没有这些字段时仍可使用，不以当前项目或模型设置补写历史。

## 验收与证据边界

- 使用一条明确的故事或剧本修改意见，执行后分别查看编剧、分镜和审核的输入清单及原始请求。
- 修改意见后新输入必须使对应缓存失效；相同输入复用时显示原始调用来源。
- 在隔离样例中验证小窗口阻止提交；旧资料仍保留。不要通过修改正在运行项目的私有配置测试。
- 页面读取、展开材料及查看来源均不启动生成。桌面和手机、明暗模式应可阅读长哈希且无横向溢出。

自动测试使用模拟响应及独立 loopback HTTP，不代表真实模型已理解反馈或作品质量提升。真实模型验收由用户在测试版主动启动，仍沿用原有费用授权。
