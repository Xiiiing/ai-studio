## 实现过程中的专项审查

云视频提交可能产生费用，因此对新增链路重点检查了“任务是否已经提交”这一事实：

- 同一镜头通过进程间文件锁串行化；另一个执行者返回 busy，不再发起 POST。
- 在发出生成请求前，将提交意图、输入签名与模型身份写入持久化回执并同步文件和目录。
- 取得 task ID 后立即保存。查询超时、下载失败、进程中断后使用已有 task/file ID 恢复。
- 提交结果不确定时保留证据并等待人工处理，不自动重新付费提交。只有服务明确确认失败的任务才进入既有有界重试。
- 配置、提示词或首帧改变时，不把原任务藏到新缓存键下继续提交。
- CDN 下载不携带 API Authorization；限制重定向、解析后的地址、体积、绝对超时和文件完整性。日志与任务回执不保存 API key、签名下载 URL 或首帧 base64。
- 首帧格式、大小、短边和纵横比，以及 Hailuo 2.3 的时长/分辨率组合，在提交前校验。
- 远程生成等待不持有本地 GPU 租约；下载原片保留，再以 FFmpeg 统一帧率、尺寸和镜头长度后进入原有审核与剪辑链路。

上述是本次新增实现的审查和修复内容，不表示原项目已经存在 MiniMax 重复收费事故。

## 展示证据的边界

当前模型分配与历史实际执行模型分别展示。旧回执缺失模型、时间或所属阶段时，不使用今天的配置补造历史；无法可靠归属的调用标注为项目历史。

回执读取限定在当前项目目录和已知回执位置，拒绝符号链接与跨项目路径，并限制目录遍历数、文件大小、回执数和每角色展示数量。失败、候选或缺失媒体不会被计为已完成交付；超过读取范围或回执无法读取时明确标记。数据流依赖边表示编排关系，不冒充已经发生的交接事件。

AI 领导与既有 LangGraph 节点继续执行任务；新页面负责让职责和执行数据可见。本次没有加入“模型临时修改工作流代码”的能力。

## 验证

最终完整 CPU 测试为 **360 passed in 21.60s**；前端为 **35 tests / 35 pass / 0 fail**，无跳过测试。相比修改前，CPU 覆盖增加 101 项。核心命令：

```bash
envs/factory/bin/python -m pytest -q tests
node --experimental-fetch tests/test_factory_ui.mjs
git diff --check
```

测试包括原生/兼容文本协议、响应模型身份、网络策略、视频提交/恢复/失败语义、并发与落盘顺序、配置 CAS、真实 HTTP API、项目证据隔离和前端交互。生产集成测试使用模拟云输出及真实 CPU FFmpeg，检查 24 fps、精确镜头时长、分辨率、完整解码和缓存复用。

另以 SQLite 只读模式抽查现有项目数据，实际返回一个等待最终确认的项目：新 flow 代码读取 94 条真实执行记录（91 成功、3 失败），生成 47 个安全产物链接，未读取到损坏回执。该项目触发有界历史截取，返回 truncated=true；页面会提示历史不完整。本次检查没有调用生产、修改数据库或输出故事正文。

没有调用真实收费云 API 或运行 GPU 模型生成；不能将本次测试解释成每家账户、每种模型版本均已在线验收。浏览器截图因 Runner 的 Firefox SWGL framebuffer 错误未完成；前端已通过真实应用模块的 DOM/API 交互测试和静态布局检查。
