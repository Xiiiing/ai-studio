# H3 自动提示词与有界返修

选择 H3 后，正常工作流会让**已配置的分镜导演模型**自动把批准镜头编译成 H3 提示词。用户填写故事与镜头要求，确认人物、画风和动作即可，不需要另写英文视频提示词。模型绑定、H3 质量档和采样参数继续由用户配置；本功能不安装或部署模型服务。

## 从批准镜头到视频

1. 分镜阶段确定剧情动作、人物／道具归属、运镜、连续性和时长，图像阶段提供首帧及已有审核结果。
2. 制作阶段显示“自动编写视频镜头提示词”，由 `storyboard_director` 的实际模型生成结构化计划：首帧状态、最多四段动作时序、结束状态、摄影机和连续性。编译专用模板为显式 `3.0.0`，普通分镜及团队安排的默认模板不变。
3. 程序验证字段和时间范围，统一渲染 Picture 1 在 0.00 秒的首帧锚点，以及 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music` 三段文本，并将这段真实提示词提交给 H3。
4. 视频生成后继续执行原有技术检查与配置的视觉审核。审核比较批准动作和画风，不把提示词编写成功当作画面通过。
5. 审核不合格时，工作流根据问题代码、原批准事实和正向约束重新编写提示词；需要新首帧时先完成首帧返修，再按实际新首帧校验和编译。达到原有次数或预算限制、审核不可用或动作无法忠实表达时暂停，已有媒体保留。

官方资料依据：[MiniMax 的本地 Context-IR 建议](https://github.com/MiniMax-AI/MiniMax-H3#h3-context-ir)、[基础提示指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)、[Comfy H3 提示指南](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide)。本地编译采用首帧锚定、可见动作时序、明确运镜和声音策略；不是托管 Context-IR 的实现或同等质量承诺。BasicGuider 没有独立有效的负向提示分支，最终模板优先使用正向画面约束。

## 配置

在应用配置的 `production` 中选择：

```json
{
  "production": {
    "h3_prompting": "automatic"
  },
  "llm_roles": {
    "storyboard_director": "my_local_director"
  }
}
```

这是配置片段；`my_local_director` 必须是 `llm_profiles` 中已有且启用的真实连接，不能整段覆盖完整配置。H3 应用工作流未填写 `h3_prompting` 时默认 `automatic`。其他视频提供商不启用本编译器。

高级使用者可设置 `manual`，直接使用已经批准的 `motion_prompt` 和旧版拼接逻辑。直接调用低层 `ProductionEngine/_Run` 的兼容调用者维持原行为；显式启用自动模式时必须提供该批次的导演配置。正常 Web/worker 工作流会冻结并传入这份配置，不要求用户手写它。

对白和配乐继续由现有音频工作流负责，H3 提示仅选择静音或环境声，原生配乐为 None；当前适配器输出视频轨，不自动接管 Qwen3-TTS 配音。同步口型要求与此模式冲突时明确暂停，不悄悄改成闭口画面。H3 镜头沿用实际适配器的 1–15 秒限制。

## 恢复、缓存与证据

提示词在 H3 GPU worker 启动前准备，文本模型请求不占着 H3 双卡租约。模型不可用、格式错误或导演报告不可执行时，不回退通用提示词、不提交视频；第一次提示编写失败也不消耗视频尝试次数。首帧返修后的提示编写故障会保留 `prompt_preparing`，恢复同一 take 和已生成首帧。

已编译待执行、已提交或已生成的任务复用保存的真实提示词，未知提交先恢复确认。编译器实现／模板、导演模型、动作、连续性、首帧、画风或参数变化会使对应旧缓存失效，不能绕过未确认任务。原有视频人工选择在动作／连续性计划变化后需要重新确认。

`attempt.json` 和视频结果回执保存 `h3_prompt`：实际模型身份、模板／实现指纹、结构化计划、输入签名、首帧 SHA-256、最终提示词哈希及尝试号。候选接口继续显示实际提示词，并附编译回执。`quality_status=pending_actual_media_review` 只表示编译完成，实际媒体质量看视频 QA。

## 已验证与限制

验证包含真正的本机 TCP/HTTP 文本接口调用与模型身份校验、结构化协议、错误／阻断处理、缓存与恢复，以及使用 CPU 媒体 fixtures 的实际生产循环：无需手写运动提示词、编译发生在 GPU 租约外、编译文本进入 H3 图、视觉失败触发新首帧和提示返修、故障恢复不重复生成。

文本导演没有直接看到首帧像素，使用批准画面描述、实际首帧标识及已有视觉 QA 线索；这些线索不是绝对事实。构图与动作忠实度仍依赖真正的视频审核。提示结构和时间校验可以确定性检查，画面美感、手部正确、身份和动作完整性不能通过文字校验保证。

按用户要求，本轮不启动额外 GPU 长测试、不部署。之前 [本地质量验证](WKP_LOCAL_QUALITY.md) 的写实人物样片由独立固定提示词生成，不能当作这套自动编译器的效果验收。
