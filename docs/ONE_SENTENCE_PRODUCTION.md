# 一句话整剧制作（0.3.4）

新模式沿用整剧、LangGraph、持久 worker、冻结模型连接和原有媒体生成器。输入一个故事方向后，系统依次规划、独立审稿、制作剧集、检查实际媒体及生成整剧交付包。最终成片由用户观看验收。历史项目和没有指定新模式的 API 请求保留原行为。

## 创建与额度

在整剧创建页启用“一句话整剧制作”，选择全部剧集并开启连续制作。表单显示集数、时长、路线及整剧固定 GPU 额度；选集制作、手动流程及导入剧本继续使用既有入口。首次真实验收规格为 H3 视频三集、每集60秒，使用自己的已授权连接和额度。

API 最小请求：

```json
{
  "production_mode": "one_sentence",
  "brief": "两位成年人在车站发现旧信，逐集查明真相并在结尾完成和解。",
  "request_id": "my-first-drama"
}
```

省略规格时，该 API 默认三集各60秒、animation 路线及原有每单元120 GPU分钟、180分钟活跃时间、3次普通尝试。UI提供三集各60秒预设，规格仍可编辑，提交时明确传入。新模式需要连续制作全部剧集；重复 request_id 沿用原幂等检查。

整剧上限在创建时固定为每单元额度 × 集数 × ceil(每集秒数 / 90)。场景细分与局部返修共享该总额，不因增加单元获得新额度；单元自身上限仍有效。等待资源不扣GPU分钟或活跃制作时间。已经发生的用量和尝试保留，未知提交先对账。GPU分钟不能代替云供应商的金额授权。

模型、提示词、生成流水线和 Agent 策略向剧集与制作单元继承。若没有配置总制片岗位，在冻结快照中复用既有策划模型；不改变全局连接。角色预检仅接受当前支持且已授权的内网推理。需要补齐连接、鉴权、视觉能力或动作协议时给出具体阻塞，不以普通文本回答冒充工具执行。

## 故事、声音与实际证据

全剧规划为每集保存2至8个具稳定ID的必要事件，分镜的 beat_ids 指向实际承载的事件。单元推进场景、单集兑现本集目标，末集完成全剧收束；不要求每个内部单元重复演完整个故事。

新模式允许每镜最多四句顺序画外音。文本容量按镜头秒数估算，检查起点及预计占用是否重叠；随后继续通过原 TTS 生成、真实音频测量和有界缩句保证时长。不会依靠过度加速或删掉关键声音偷偷通过。

H3使用真实动作视频、外部配音和字幕，不承诺口型同步。新模式不把全程闭口作为默认全站要求；用户和具体镜头明确要求的闭口约束继续通过真实采样证据检查。其他历史路线保持原合约。

镜头生成、技术检查和独立审核后，系统从导出视频抽取必要事件对应镜头的起始、中间、结束帧，并核对事件及末态。按事件分批审核，不为适应上下文静默删掉必要采样。明确失败交回对应镜头/单元有界返修；证据不足、未知提交或额度耗尽保留产物并停止。

后续剧集固定前集实际末态、文件哈希、采样位置与证据范围，不能将计划末态冒充已经发生的结果。抽样图片不能证明未采样时段或听过完整音轨；声音仍以实际音频时长、字幕和既有技术检查为依据，艺术效果仍需观看验收。

## 后台执行与交付

角色调用前只检查所需的模型；图像、配音和视频在各自提交边界检查所需服务。缺视频资源不阻止独立文字规划。已知临时资源故障延期同一个持久任务；暂停、取消、鉴权错误、结果未知与额度耗尽不会伪装成可无限重试的网络故障。

全部剧集通过成片事件检查后，worker 创建独立的整剧检查任务，核对因果、相邻集状态和末集结局。明确矛盾按集号与实际镜号有界返修，返修记录和用量保留；上游版本变化使旧承接失效，后续集重新采用实际末态。通过后生成固定版本 ZIP，包含逐集带字幕/无字幕视频、字幕、时间线、技术检查、单集事件证据、整剧审核及原有制作清单。

整剧响应新增 whole_drama_budget 和 delivery_bundle；包的 current 字段表示是否匹配当前全部剧集。固定版本下载使用原下载端点的 bundle 参数；普通下载继续支持部分成果及未完成原因。自动通过表示工程与抽样检查完成，不表示人工终审、平台发布或商业效果保证。
