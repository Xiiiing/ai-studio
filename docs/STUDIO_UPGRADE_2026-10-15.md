# 制作工作台与执行契约重构

## 基线与范围

本轮从交接分支 `wip/console-refactor-handoff-20261015` 的 `9560a83` 接续，在 `codex/studio-upgrade` 开发。Wkp 正式版本与这个基线不同；本报告描述本地源码和隔离验证，不声称生产服务器已经升级。

用户确认采用浅色制作工作台与 Agent 指挥中心，新项目默认 AI 代管故事和视觉方向，人工仍负责终审、增加预算和费用授权。按用户后续指示，本轮没有读取实时生产日志。

## 已确认问题与修复

| 问题 | 改变后的行为 |
| --- | --- |
| 创作审稿异常被归为模型运行故障 | worker 保留结构化审核证据，反馈进入对应创作恢复步骤 |
| 待办声明补素材、切原创等操作，却没有处理接口 | 统一动作注册表同时生成字段、选项、可执行状态和处理函数 |
| 旧关卡可携当前项目 revision 提交 | 人工和总制片共用当前代数、候选资格和审核/产物版本校验 |
| 缺少视觉全部否决路径，视觉反馈不被消费 | 独立视觉代数、反馈重设计、历史预览保留，累计用量不清零 |
| 聚合创作节点无法定位失败和恢复位置 | v2 分别保存目标落实、剧本、分镜、独立审核与视觉设计步骤 |
| 静态画布与实际图漂移，团队工单未接入 | 工作区、画布、工单和产物使用实际执行定义与回执 |
| 最近项目截断导致待办不可达 | 全量统计，项目与待办独立分页，明确返回分页范围 |
| 局部意见可能改写未指定镜头 | 新版创作路径保留镜号范围、未修改镜头、角色和视觉设定 |
| 审稿 DB 写入后 checkpoint 前崩溃可能重复计轮 | 审稿结果绑定实际稿件轮次，恢复复用已保存的分支决定 |
| 复用旧素材被当作当前版本新执行 | 原执行版本与当前引用版本分开，未知历史保持未知 |

## 界面与接口

前端统一为 React、TypeScript、TanStack Query 与 React Flow。项目首屏优先展示当前产物、任务与下一步，完整工作流可以展开。故事、视觉、分镜、镜头、成片、系列资产、模型连接和费用仍有实际操作入口。

`/api/factory/console` 提供全量统计和独立项目/待办分页；`workspace` 返回项目、执行图、工单、审核、代管状态和动作。客户端根据服务端 descriptors 渲染处理表单，提交绑定编辑开始时的版本；冲突保留输入并要求核对。

新项目默认 `workflow_version=2` 和 `team_mode=delegated`。总制片未配置时明确显示人工接续原因。人工接管在安全边界暂停，晚到的 AI 答案必须重新通过 mode、revision 和证据校验。旧项目没有版本字段时按 v1 恢复，不替换原 LangGraph 检查点。

制作观察记录镜号、尝试、角色、审核、配音、对白和后期阶段。节点返回、产物存在、独立审核通过、出品人批准分别表达；没有执行的步骤显示无需执行。

旧 UI、旧启动器和固定样片专项验收模块删除；退休 HTTP 地址保持 410。`studio/` 中当前制作仍使用的适配器、媒体边界和 Range 播放保留，`legacy15` 继续作为既有制作规格的存储身份。

## 构建、验证与交付

UI 在构建机执行 `npm ci --ignore-scripts`、`npm test`、`npm run build`，输出 `ui/factory/dist`；完整运行依赖授权随静态包保存。Python 同源提供静态资源，运行服务器不需要 Node 服务。`npm run dev` 持续构建，另一个终端运行 Python Web 服务并打开同源入口。

验证使用独立临时 SQLite、公开示例配置、合成媒体和禁止生产调用的 fixtures。回归包括真实 Python HTTP、持久化图恢复、角色与审核证据、动作恢复、配置协议、React 组件及 Chromium 页面。
