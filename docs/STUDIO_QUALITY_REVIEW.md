# 工作室整合使用检查（2026-10-16）

本轮在统一素材库与五阶段流程图整合后，使用独立本地数据检查工作室各页面。流程保留阶段连线、内部步骤和执行时的数据流动效；不需要缩放或拖动画布。

## 修复结果

- 多图保存失败会保留文字草稿和未完成文件。已保存的图片不重复上传，剩余图片可移除、替换或继续保存；不支持的文件先校验，再建立素材。
- 新建素材切换类型时清除原类型的组合字段，保留名称和说明，避免后台拒绝看似正常的表单。
- Markdown 配图和链接按文件所在目录解析；保存回执中的 `production/...` 路径也可阅读。图片仍限于对应项目的文件边界，原始 HTML 不执行。
- 媒体预览失败提供明确状态和重新读取入口；原文件下载继续保留。
- 素材选择读取服务端的实际角色，兼容规格保存在 episode 内的项目；角色数据晚于图库到达时不会提交默认的错误角色。
- 项目素材选择随项目版本及定时刷新更新，避免其他窗口已修改项目后仍一直使用旧版本。素材库、项目选择及任务读取失败分别提供重试，不冒充空列表。
- 参考图片可在页内放大查看并下载。手机项目导航自动换行，十个入口通过正常页面滚动即可访问。
- Agent 执行关联包含已确认素材的签名。更换定稿后，旧执行转入历史；仅修改待定稿选择、或再次确认相同固定版本，不会使原执行失效。

## 实际验证

UI 测试、Python 工作流与提供商契约、生产构建及 Chromium 浏览器检查使用仓库 CI 相同入口。新增真实 Python HTTP 浏览器夹具，使用临时 SQLite、项目归属回执、Markdown、JSON、调用重试原文和图片文件。

Chromium 在 1440、1024、390 像素逐页检查七个工作室页面、十个项目标签，共51个页面组合；检查错误状态、页面宽度和全部手机导航入口。另实际操作了：

1. 打开故事目标 Markdown、表格、相对图片和分镜附件，阅读剧本草稿；刷新后保持选中步骤和已打开文档。
2. 查看当前执行的第二次请求原文，确认 `prompt` 保留，历史执行不会标为当前步骤。
3. 在真实 HTTP 服务上传一张正常图片和一张损坏图片，保留草稿、替换失败文件，继续保存到正确固定版本。
4. 放大图片、下载原图，新建暂停的素材准备项目，选择实际稳定角色并确认定稿。
5. 第二个客户端修改项目后，等待开放页面同步，再次定稿使用最新版本。

原有浏览器检查继续覆盖故事/视觉/终审决策、模型连接配置、播放与刷新、失败文件和超限文档、返修连线、动效停止条件及键盘操作。这些决策和模型配置检查使用模拟提供商响应，不代表真实推理效果。
