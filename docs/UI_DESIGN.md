# 工作台 UI 设计与兼容约定

工作台采用大面积白黑中性色、有层次的可选主题色和少量必要语义色。该约定覆盖全局视图、项目页面、共享弹窗及明暗主题；整剧流程与自动返修规则见[整剧制作](DRAMA_PRODUCTION.md)。

## 视觉与交互

- 白黑及中性灰用于页面、面板、大卡片、正文、主按钮及全局导航；主题色集中于当前工作和下一步操作附近，并在导航位置、项目内选中项、焦点和真实进度上少量呼应。失败/紧急用红，待处理问题用黄，通过用绿，限于有意义的标签、图标、细边和局部提示，不铺满大卡片。中性与语义颜色由`styles/tokens.css`定义，主题色由`styles/accents.css`覆盖，并配合文字标明状态；明暗主题正文和按钮满足AA对比度。供应商官方Logo与实际素材保持原色。
- 品牌统一使用 README 已有的[电影画框与金色星芒 Logo](assets/logo.svg)，保留原图形与原色。`ui/factory/public/brand.svg`是该资产的完整副本，单测校验逐字一致；更新原资产时同步复制，侧栏`BrandMark`与浏览器图标均引用该副本。移除英文装饰副标题、侧栏重复底座和宣传页脚；流程阶段显示中文，保留影响操作的预算、审核问题、来源和版本提示。
- 每页保留一个主标题和明确操作区，移除英文装饰标题与无功能头像。主题色按工作位置分配：当前项目、正在进行的阶段与下一步操作组成连续的视觉重点；数量、筛选结果和服务连接数属于辅助摘要。主题色在工作区背景渐隐，并呼应当前导航、真实进度和流程选中态；普通表单与阅读面板保持中性。相同信息不在概览重复堆叠；详情通过分组或展开查看。
- 主题按钮以显示器、太阳、月亮表示当前偏好，按 system → light → dark → system 循环。悬停和聚焦说明当前与下一模式；原 `studio.theme` 值、系统变化跟随与跨标签同步保留。存储不可用时仍支持本次会话切换，初始化脚本在样式渲染前应用主题。
- 正常同步状态为小型指示，异常保留明确文字；图标操作提供可访问名称，所有业务决定保留文字、确认与版本检查。项目状态入口常驻标题旁，长期问题按需打开详情抽屉；请求失败与临时反馈使用固定通知区域，不插入导航上方。表单保留就近错误和草稿，长错误可查看详情。

文字层级及反馈交互沿用[UI二轮收敛](UI_REFINEMENT_ROUND2.md)，颜色与自有品牌以本页为准。

## 参考图与设计模型

本轮依据用户提供的三张后台界面参考图提炼设计方法。图中相近的卡片语言、浅色画布、黑白导航与局部绿色焦点共同构成层级；能源设备图和统计图服务于各自业务。本应用将其转为影视制作语境，保留制作导航与真实流程，新增系统设置入口，继续提供六款主题。

| 设计方法 | 参考图表现 | 在映序中的实现 |
| --- | --- | --- |
| 画布、容器、内容三级 | 浅灰外底、浮动圆角工作区、白色内容卡 | 桌面圆角外框、轻边与低阴影，统一16px内容卡；手机使用全宽空间 |
| 视觉权重分配 | 标题、主数据、辅助文字有明显尺寸差 | 当前项目标题优先，四项真实制作指标用大数字，事件和资源作为次级内容 |
| 同组靠近、同类一致 | 模块对齐，卡片间距与内边距有规律 | 统一间距与控件圆角，任务与待办组成主区域，动态与资源置于其后；项目、模型与流程共用面板语言 |
| 颜色面积与职责 | 黑白承担大面积信息，绿色卡片从浅色经过较浓的局部色彩，再柔和过渡到浅色，形成中等面积视觉重心，语义色占少量 | 阅读、导航、主按钮与普通进展指标使用系统中性色；所选主题色从当前工作与操作区域向画布渐隐，选中位置与真实进度呼应；语义红黄绿只用于实际状态 |
| 颜色服务于信息 | 绿色卡片承载业务数据，图形服务所属业务 | 当前工作区连接实际阶段、可用制作进度和下一步入口，已有首帧仅作缩略图；GPU条来自真实回执，不生成虚构曲线或节省时长 |
| 操作与内容相连 | 焦点模块有明确出口 | 总览优先选择待处理项目，其次执行中、未完成及最近项目；“打开当前项目”进入服务端指定的待处理阶段。无项目时提供“新建一部剧” |

总览的项目说明、阶段、真实进度与打开按钮位于同一个工作区域：桌面说明在左，阶段和操作在右；手机按说明、阶段、进度、操作顺序排列。主题渐变通过遮罩融入右侧操作附近的画布，不再给阶段单独画一张彩色卡。整剧与长集也优先显示当前工作及其入口，已出片数、完成单元数以紧凑摘要排列在下方。项目标题完整换行，按钮保持44px触达；可选首帧缩略图加载失败时回到图标。外观是界面层更新，不改变模型、角色、审核或生成配置。

整体布局与颜色位置集中在`styles/theme-layout.css`，基础组件样式位于`styles/studio-design.css`，通过中性token定义边框与阅读区，通过独立主题token定义随明暗变化的柔和渐变；不引入新的设计组件依赖。关键行为和六款配色保持原检查，增加真实焦点选择、空态创建、长中文标题、彩色焦点与中性阅读区分工、明暗及桌面/手机检查。[本轮界面与复现](images/studio-design/README.md)。

## 外观设置

从左侧“系统设置”进入外观显示，手机先展开主导航。右上角调色板按钮已移除，快捷明暗模式切换保留。`#view=settings`旧链接仍默认显示外观；`tab=appearance|models|runtime|about`定位具体分类，刷新与前进后退保留位置。外观显示提供显示模式（跟随系统、浅色、深色）与六款主题色。点选即时应用到当前工作背景、导航位置、项目内选中项、焦点、进度和工作流选中态；主按钮与阅读区保持中性黑白；页面展示真实主题 token 的效果预览，无需保存按钮。外观显示不依赖业务API可用性，也不写入模型、项目或服务器配置。

| 主题 | 设置色卡方向（明暗共用） | 视觉方向 |
| --- | --- | --- |
| 深灰蓝 | 雾蓝高光 → 蓝灰 → 冷白 | 保留默认偏好，降低沉闷感 |
| 雾银 | 银白 → 冷银灰 → 雾白 | 中性层次 |
| 薄荷青 | 浅薄荷 → 清透青绿 → 薄荷白 | 参考图中的清透青绿 |
| 青柠绿 | 浅青柠 → 清亮嫩绿 → 淡绿白 | 参考图中的局部绿色重心 |
| 雾紫 | 浅薰衣草 → 柔和紫 → 紫白 | 冷暖平衡的浅紫 |
| 杏桃 | 奶杏 → 柔和杏桃 → 杏白 | 温暖但不使用紧急红 |

重新参考[Happy Hues 12 的灰紫与柔粉搭配](https://www.happyhues.co/palettes/12)、[Happy Hues 14 的黑白与浅青层次](https://www.happyhues.co/palettes/14)及[Radix 色阶的背景、边界与文字职责](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)，结合用户参考图自行设计六组渐变，不直接套用其整页颜色或按钮颜色。

总览、整剧及长集的当前工作区，以及单元工作台的“当前任务与下一步”区域，使用与当前面板混合并向画布渐隐的主题背景。共用 PageFocus 仅展示紧凑中性摘要，设置效果预览用于说明配色。`--feature-glow`、`--feature-color`、`--feature-mist` 从所选配色和 `--panel` 派生，保留三站不同颜色及自然过渡；文字使用 `--feature-ink`，边界与高光也随当前模式协调。

浅色模式工作背景中心混色比例为 68%，两端为 18% 与 9%；深色中心为 28%，两端为 8% 与 6%。径向遮罩让背景在操作附近保留颜色，向说明与周围画布渐隐；手机调整遮罩位置适应纵向阅读。设置预览中心分别使用 54% 与 20%。中心比例在实际工作区作用域重新计算。业务文字检查完整渐变与站间插值的 AA 对比度，渐变与周围面板的最大亮度对比控制在 3:1 内。

设置中的六张小色卡保留配色身份与原偏好 ID，效果预览则使用实际明暗渐变。`--accent`继续服务选中、焦点和进度，主操作及阅读面板保持中性，红黄绿语义状态和品牌、用户素材颜色不变。

显示模式沿用`studio.theme`，主题色单独保存在当前浏览器的`studio.accent`，以白名单校验；无效值回到深灰蓝。偏好不跨设备同步，同源标签页通过storage事件同步。存储不可用时本次会话仍可切换；由根Provider保留会话状态，页面切换不重置。`theme-init.js`从构建静态路径在首屏加载前应用两项偏好，避免依赖React挂载后才恢复颜色。

单测校验六套配色在明暗模式下渐变全程与文字、黑白主按钮、主题文字和焦点对比度，浏览器实际检查六款切换、键盘选择、刷新恢复、跨页与跨标签同步、首屏脚本、API不可用和手机布局。[设置页截图与复现](images/appearance/README.md)。

## 跨页面颜色覆盖

同一颜色职责应用于全部视图及桌面/手机，编辑页不为凑颜色重复插入摘要。共用`WorkFocus`组织当前工作与下一步，共用`PageFocus`提供紧凑中性摘要。摘要数据与进度直接复用各页已有快照，未知进度不展示填充条；阅读区、表单、主按钮维持黑白。

| 页面 | 业务重点 | 阅读、编辑和选择规则 |
| --- | --- | --- |
| 总览 | 项目说明、实际阶段、可用进度与打开入口组成一个工作区域 | 四项指标、任务、待办、动态和资源卡保持中性 |
| 项目 | 当前搜索/分类的匹配总数；无总数字段时明确使用当前结果 | 项目表、搜索、筛选、分页保持中性，选中项细边/下划线 |
| 素材库 | 全局为本页素材数；剧内为已读取的固定版本绑定数 | 人物、场景、画风、组合参考和素材编辑弹窗保持中性；原图与裁剪选区按实际用途保留 |
| 运行记录 | 本次载入事件数，不宣称全量历史 | 分类筛选和事件正文中性，真实错误、审核与完成记录以小状态标记区分 |
| 模型配置 | 已配置的服务连接组数，不代表连接验证通过 | 服务连接与配置操作优先展示，摘要置于列表之后；制作分工、高级工具及编辑弹窗共用中性底；连接结果用真实回执的标签或细边 |
| 整剧 | 当前阶段与制作/规划入口优先；已出片剧集数放下方辅助，等待验收不等于人工通过 | 规划、共享设定、剧集、批次、成果均保持中性；真实选中流程节点使用主题细边 |
| 长剧集 | 当前阶段、剧集说明与制作流程入口优先；完成单元为辅助摘要，不等于整集通过验收 | 场景/单元、长时间轴、流程、字幕、播放与验收区使用同一规则 |
| 单元/历史短片工作台 | 当前任务与下一步操作区承接主题背景；阶段、预算等事实保持同级中性摘要 | 剧本、素材、镜头、审核/质检、团队、费用与交付页保持中性阅读与编辑，选中镜头/候选/版本用细边或下划线 |

流程节点、团队任务、返修选项和镜头列表的选中态不再整卡染浅主题色；普通通知及运行中标签采用中性正文与底色，实际运行点保留主题色。等待人工处理显示黄色标记，失败显示红色标记，通过显示绿色标记；状态文字始终保留。供应商品牌与用户媒体维持原色。该规则覆盖异步加载、失败反馈、弹窗与可滚动窄屏，不修改制作/审核或模型连接配置。

新增跨页浏览器检查使用非空整剧、分集、共享资产、批次、镜头、对白、字幕、质检、团队与费用样本，检查明暗/桌面/手机以及六款主题跨页保持，读取页面不提交业务请求。截图及覆盖矩阵见[跨页证据](images/all-pages-color/README.md)。

## 系统设置

系统设置采用分类导航与内容区，桌面分类位于内容左侧，窄屏排列在内容上方并换行，不增加嵌套滚动。外观显示继续提供浏览器本地偏好；模型与服务复用同一模型配置组件，保留服务连接、制作分工、高级工具、未保存分工和版本检查；模型管理统一从“系统设置 → 模型与服务”进入；旧 `#view=models` 地址替换为 `#view=settings&tab=models`，不增加浏览器历史记录，不再保留独立模型页面。

运行状态读取现有控制台的执行器、队列、并发上限、任务持久化、制作能力及 GPU 观测数据，不将未知状态显示为零或连接成功。关于与版本通过只读`GET /api/factory/system`读取服务版本、进程启动时的代码提交、启动时间和显式标记的部署环境，同时显示当前访问入口。服务版本沿用后端`factory.__version__`，代码提交独立展示，不替代产品迭代号；源码不含 Git 或环境未标记时明确显示未提供/未标记。

系统信息接口仅返回上述公开身份字段，不读取私有模型配置或输出数据目录、主机信息与凭据。API 暂时不可用时可重试版本/运行状态；外观修改继续独立可用。界面与实际配置保存检查见[系统设置证据](images/system-settings/README.md)。

## 选中态

主导航保留原有黑白反差选中态，不随六款主题改为彩色背景。第二级系统设置分类使用中性面板、完整细边、较高字重与末尾勾选，去除该分类左侧的竖条。其它制作页面与外观选项保留原有设计。键盘焦点独立使用外轮廓，选中不改变尺寸或内边距。

[桌面与手机截图](images/navigation-selection/README.md)使用隔离 API fixtures，非真实模型生成。

## 桌面外框与滚动

桌面外框固定在视口的上下边距内，侧栏与其共享顶部、底部和圆角边界，主内容在右侧独立滚动。长导航列表继续单独滚动；路由切换回到主内容顶部。弹窗锁定主内容滚动，关闭后恢复原位置，手机继续采用页面滚动和抽屉导航。短页面及改变窗口高度也保持外框完整。

布局参考 [Mantine AppShell](https://mantine.dev/core/app-shell/) 与 [shadcn Sidebar](https://ui.shadcn.com/docs/components/sidebar) 对固定布局和滚动内容的分工，没有引入这些库。[顶部与底部截图](images/navigation-selection/README.md)配合外框几何、长导航、路由复位、弹窗恢复和窗口高度变化检查。

## 导航与内容

侧栏采用扁平导航，按顺序显示总览、项目、素材库、运行记录、系统设置，不再显示“工作室／管理”分组及全局“流程与团队”入口；近期项目仍可直接访问。模型连接、制作分工及高级工具集中在“系统设置 → 模型与服务”，模型地址、角色分工和工作流定义不因导航调整而改变。

待办集中在总览，直接进入对应项目及需处理阶段。完整列表沿用独立待办分页查询，每页最多100项，不限于最近项目；分页失败可就近点击“重新读取待办”，错误仍通过统一反馈区显示。旧`#view=inbox`链接显示总览，旧`#view=workflow`显示项目列表；保留原地址及浏览器历史。具体项目里的工作流、团队和执行回执入口继续使用。

| 主入口 | 原 hash 与子页面 |
| --- | --- |
| 概览 | `overview`：作品、当前问题与下一步；进度和预算为摘要，流程/团队/背景和事件按需展开 |
| 剧本 | `script`：正文、人物与逐镜分镜 |
| 素材 | `materials` 项目素材与定稿；`series` 系列资产 |
| 镜头 | `shots`：当前视频与首帧、审核结论、紧凑版本记录与单镜精修 |
| 审核 | `decisions` 待办决策；`quality` 质检记录 |
| 交付 | `delivery`：现有成片播放与下载 |
| 更多 | `team` 团队回执；`costs` 云任务与费用 |

旧 hash、前进后退与深链接不重写。主页面和子页面各自明确选中状态；窄屏保留六个主入口与更多，不使用第二层竖向侧栏。

镜头预览默认每种素材显示一个版本：已选定版本优先，其次当前参数下可预览素材，再次历史可预览素材。历史预览有来源提示；如果当前参数的新版本审核尚未完成或失败，会另列当前参数结论。历史转为紧凑列表，用户显式选取两个版本后比较，不触发生成或保存。选片仍要求确认、可选资格和原版本检查。

模型服务以用途、供应商/模型与地址区分；连接和制作分工保持独立。模型 ID、协议、上下文、密钥关联与 TLS 能力由现有接口提供，不根据 Logo 推断。完整参数和原始回执按需展开。

- 浏览器覆盖全部6个主导航页面、系统设置各分类、旧全局链接及10个项目页面，浅深两套主题及320/390/768/1024/1440/1920宽度，检查溢出、按钮可达、旧链接与历史、草稿、表单保存和作品下载。
- 交互使用独立 fixtures 与独立临时 SQLite；真实 HTTP 测试使用测试 Python 服务。色条媒体、模拟模型与审核数据均为测试材料，不是模型推理或制作质量验收。
- 模拟验收不操作正式项目，不调用真实生成；cami测试版按授权更新，实际只读检查与备份另行记录，不自动合并或更新稳定版。历史截图见[UI改造证据](images/ui-unification/README.md)，当前配色、品牌和审核返修界面见[本轮证据](images/review-return/README.md)。
