# 整剧与批量制作

新建项目默认代表整部剧；原单集入口保留，旧项目与旧检查点不转换。全剧可由梗概创作，或粘贴/导入UTF-8 TXT、Markdown剧本（至多60000字）。填写总集数、目标时长、题材、画风和H3/动态漫路线。

策划先整理来源、世界、人物、声线、场景、道具与故事主线，再逐集生成大纲；独立审稿通过后等待用户确认。修改规划后先重新审核，再确认追加版本。已经开始的剧集保留原版本；未生成剧集在新批次固定当前版本。全剧最多16位具名成年角色，短片规格每集最多4位，声音ID来自现有固定声线。

确认规划后勾选一集或多集生成。各集由原有LangGraph工作流执行：从已确认大纲进入故事落实、编剧、分镜、独立审稿、视觉方案、制作与后期。不会重新发起三套无关故事提案。自动视觉选择仍要求已配置的总制片角色与合格审核回执；不足时保留进度并报告阻塞。最终停在待验收，由用户观看并批准或返修。

整剧、剧集、内部制作单元均保存在原SQLite `projects`快照，以`record_kind`、`drama_id`、`parent_id`关联；批次和请求幂等记录在整剧版本快照内，不建立第二套队列。新版使用`workflow_version=3`，旧版1/2保持读取与恢复。新接口沿用Host/Origin边界、体积限制和版本检查。

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/factory/dramas` | 列出/建立整剧 |
| `GET /api/factory/dramas/{id}` | 规划、剧集、批次与影响范围 |
| `GET /api/factory/dramas/{id}/episodes` | 剧集列表 |
| `GET /api/factory/dramas/{id}/batches` | 批次及当前成员状态 |
| `POST /api/factory/dramas/{id}/confirm` | 确认规划或提交修改后重新审核 |
| `POST /api/factory/dramas/{id}/generate` | 指定`episode_numbers`创建生成批次 |
| `POST /api/factory/dramas/{id}/actions` | 整剧、批次或单集暂停/继续/取消/重试/验收/返修 |

变更请求携带`expected_revision`与`request_id`。同请求同内容返回已记录结果；不同内容复用请求号会被拒绝。批次保存规划版本、配置签名、私有执行配置及单元预算，公开响应剔除私有执行配置。

默认按集号顺序进入原worker，一集失败后继续无依赖集；明确依赖其未确定结果的后续集等待。暂停/取消在安全边界生效，完成素材不删除。预算与自动尝试上限沿用既有执行器，重试不会清零生成或审稿次数。角色、镜头、生成任务与产物都有版本归属。

本阶段验证用隔离SQLite、模拟执行器和真实loopback HTTP；浏览器使用模拟API完成1440/390宽度选集与批次操作，以及UTF-8剧本导入。截图位于`docs/images/drama-010/`，不是模型生成效果证据。生产未部署。
