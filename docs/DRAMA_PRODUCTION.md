# 整剧、多集与长剧集制作

一个项目代表一部剧，下面是剧集、场景和内部制作单元。新建项目默认进入整剧入口；原单集入口、`/projects` API、工作流1/2及历史检查点保持可用。新版使用工作流3，复用SQLite、LangGraph、worker和已有媒体执行器。

## 使用流程

1. 从梗概开始，或粘贴/导入UTF-8 TXT、Markdown剧本（最多60000字、文件240KB）。填写总集数、题材、画风和制作路线。默认每集300秒，支持15–900秒；15–90秒继续按短片规格制作。
2. 系统分块整理来源，建立全剧世界、故事主线、人物身份与声线、场景、道具和分集大纲，再以独立任务审稿。审核失败自动退回策划和编剧，携带原稿及逐条问题返修后复审，默认最多三轮；不会在首次拒绝时结束。编剧与审稿可以共享同一模型，任务、提示词、上下文和审核记录分别保存。
3. 查看待确认问题，编辑并确认全剧规划。修改过的规划先重新审核，失败也按同一返修闭环推进；审核通过后再确认。暂停或异常恢复保留当前轮次及已完成调用；轮次用尽后明确提示，用户继续规划才开启新的三轮额度，历史稿件、问题与调用记录保留。人物最多16位；短片规格一集最多4位；长集每个制作单元和每镜最多4位。
4. 勾选单集、连续多集或任意集数，设置每单元预算后启动。按集号顺序制作；失败集保留进度，无依赖的其他集继续，明确依赖其未确定制作结果的集等待。
5. 系统按已确认大纲自动编剧、分镜、审核、生成素材、配音和剪辑，执行有界返修。最终停在每集“待验收”，由用户观看、通过、指定局部修改或重新剪辑。内部单元完成只记为`unit_ready`，不会写成人工终审通过。

整剧默认打开项目总览，显示规划、剧集与待处理事项；顶栏分别打开全剧规划、共享设定、剧集、批次、成果及“制作流程与团队”。规划尚未确认时，各页显示对应的准备状态和下一步入口，不再重复显示规划编辑器。页签写入地址，支持刷新、浏览器前进与后退。

在项目总览点击“打开制作流程”，查看规划、审核、确认、制作和验收的实际进度；展开团队任务可查看负责角色、输入摘要、结果和审核问题。规划任务从已保存的调用回执读取，缺少回执时明确提示，不把尚未执行的步骤标成已完成。整剧流程可进入对应剧集，长集可继续进入制作单元的团队工作台，查看具体镜头任务、执行回执和产物。长集总览仍提供场景/单元进度、播放、下载与局部修改。桌面和手机均可选集、启动、暂停、继续、观看和提交返修。

## 共享版本与来源

规划确认追加不可变版本；人物身份、声线、场景、道具与画风随版本固定。新批次固定当时的规划、私有执行配置、配置签名和预算，修改当前设定不会改写已制作成果。页面列出仍引用旧设定的剧集。

已有剧本保存完整来源、分块分析、拆集大纲和待确认问题。识别“第一集”“第1集”“EP1”等集号；没有标题时按比例分段。逐集/逐单元创作使用有界原文片段与已审核大纲，片段不是完整源文，也不是逐字复现承诺。

共享参考图通过原有图像执行器生成、技术检查和视觉审核。通过后复制到整剧的版本目录并固定哈希，后续单元直接复用。生成任务和费用归属首次生成的单元。损坏、缺少审核回执或版本不符的参考图会阻塞，不静默替换。镜头引用角色、地点和道具；超过图像接口四张参考图时分层合成并审核，不丢弃角色身份。

存在制作依赖时，首次执行固定前集的剧本结尾、规划版本和成片签名。前集后续返修不会静默修改本集上下文，整剧页提示受影响集。承接依据是固定剧本与交付回执，不宣称完整观察前集全部视频。

## 长集编排与合成

长内容按“全剧大纲 → 单集场景 → 至多90秒执行单元 → 镜头”展开；不在一次调用中输出15分钟全部分镜。场景规划独立审核，校验总时长、地点/道具引用及角色数，最多三轮。单元按顺序承接上一单元的剧本结尾和末镜连续性。

单元使用原有编剧、分镜、视觉审核和媒体执行器。相邻单元连续性审核发现矛盾时，自动将问题和前单元实际结尾交回对应单元，定向返修其开场后再次审核；其他单元及原素材保留。按预算中的最多尝试次数限制，默认最多三轮审核；用尽后等待用户决定或显式继续，不无限生成。H3只允许当前返修版本指定镜头且输入确有变化时新建take，其他既有视频保护和不确定任务续查保持生效。视频路线通过H3逐镜图生视频；动态漫通过关键帧和程序运镜。固定角色声线，逐句配音、音轨和字幕按单元时间轴对齐。严格口型同步不属于本次验收。

对外时间线使用`E001-C01-U001-S01`这样的稳定标识；工作台内保留局部`S01`。完成单元后抽取相邻单元的结尾/首帧，检查人物、画风及明显承接矛盾；审核覆盖范围明确为交界抽帧，不声称完整视频语义覆盖。

先合成场景，再合成整集。FFmpeg统一24fps、音频采样率和单元时长；字幕加上累计偏移；检查总时长、分辨率、音轨和可解码性。缓存按源交付签名、版本和实际文件哈希验证，返修后重用不受影响的单元，输出新的不可变release目录。

局部修改可以指定单元和镜头，或由剪辑角色定位受影响单元。重剪支持重排已有单元并保持同场景连续；无法通过重排落实的意见会明确阻塞，不声称已完成新动作或新对白。修改镜头可进入单元工作台进行。每集提供带字幕MP4、无字幕MP4、SRT、时间线、技术检查与制作清单；整剧/批次ZIP按`E001/`组织，根清单列出未完成集的状态与原因。

## 恢复、预算与数据

整剧、剧集、单元仍保存在`projects`快照，以`record_kind`、`drama_id`、`parent_id`关联。批次与请求幂等记录也在整剧快照内，不建立第二套队列。备份审计检查剧集/单元双向关系、固定规划及批次归属；恢复保留检查点与版本，不自动开始生成。

生成和控制请求携带`request_id`与`expected_revision`。相同请求相同内容重放返回记录，不重复排产；复用请求号修改内容会被拒绝。验收/返修还需`expected_episode_revision`，避免批准已变化的成片。

默认每单元120卡分钟、180分钟时间上限、最多3次尝试。预算按单元累计，显示单集和批次已花费卡分钟；完成场景规划后显示授权上限，规划前明确为待计算。重试保留已有调用、生成次数和费用，不重投状态不确定的任务。全剧规划、单集场景或连续性审核次数用尽后，用户明确继续/重试才开启新的返修周期，历史记录保留；新周期不清空媒体预算。新的明确返修意见形成新的创作版本，已有费用继续保留。

暂停/取消在创作任务、媒体任务或合成安全边界生效，成功素材保留。取消后不自动恢复；暂停/失败可继续。模型任务提交前保存持久任务ID，超时、重启或结果不确定时先续查该任务；无法核实的外部执行阻塞等待处理，不盲目重投。合成中暂停只终止本次拥有的FFmpeg进程，保留完成的场景缓存。

## API

新接口沿用业务鉴权、Host/Origin边界、输入体积限制和乐观版本检查，浏览器不直连Wkp模型端口。

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/factory/dramas` | 列出/建立整剧 |
| `GET /api/factory/dramas/{id}` | 规划、剧集、批次和版本影响 |
| `GET /api/factory/dramas/{id}/episodes` | 剧集列表 |
| `GET /api/factory/dramas/{id}/episodes/{episode_id}` | 单集及单元详情 |
| `GET /api/factory/dramas/{id}/batches` | 批次状态、进度和预算 |
| `POST /api/factory/dramas/{id}/confirm` | 确认规划，或提交修改后重新审核 |
| `POST /api/factory/dramas/{id}/generate` | `episode_numbers`创建生成批次 |
| `POST /api/factory/dramas/{id}/actions` | `pause/resume/cancel/retry/approve/revise/reedit` |
| `GET /api/factory/dramas/{id}/download?batch_id=…` | 整剧/批次已完成成果及未完成说明 |

`actions`可用`episode_id`或`batch_id`限定范围；验收与返修明确选择一集，返修可带`unit_id`和`shot_ids`。公开响应剔除私有执行配置。原有业务API继续可用。

## 服务与验证边界

公开配置见[Wkp服务接入](WKP_SERVICES_010.md)、[控制层示例](../config/factory.wkp.example.json)和[推理层增量示例](../config/wkp-inference.example.json)。文本8095、视觉8098，经受控网关路由；8791持久任务层调用8352图像、8346 H3和按需TTS。图像GPU4、H3 GPU6/7；TTS只租用服务声明允许的GPU，示例为5。业务执行机负责媒体后期。

测试使用隔离SQLite、模拟角色/媒体生成器、真实loopback HTTP和真实CPU FFmpeg。300/900秒测试实际合成并解码成片，检查总时长、字幕偏移、角色声线、镜头唯一标识、缓存与恢复；它们不证明真实模型画质、剧情质量或15分钟GPU性能。浏览器以模拟API和短合成视频检查桌面/手机交互。[截图与复现说明](images/drama-010/README.md)。

本次应用接入已只读核实服务健康、模型ID、上下文和能力；用户先前的“已验证”作为部署信息单独保留。未执行新的完整真实模型长集生成，未合并、部署或修改生产数据。
