# 角色交接与定向补料

工作流的岗位连线说明职责；保存的输入/输出可以用来核对内容。
从本功能启用后的创作开始，控制层另外保存独立交接单，不能用前两类信息代替它。
历史项目没有交接单时显示“尚未记录”，读取页面不会补造历史或启动生成。

## 查看交付

在固定工作流画布上展开部门和岗位，点击节点或连线查看摘要，再打开“工作与交付详情”。
“控制层交接与补料”先展示记录摘要，按需打开版本依据或“交付原文”。所有内容沿用同一详情卡片的阅读区域，不改变画布坐标、缩放或页面位置。
节点显示相关岗位的交接，连线按交付方向筛选。较长历史按每页 30 条读取；无对应记录时明确提示。

交接状态的含义：

| 状态 | 证据及限制 |
| --- | --- |
| 待接收校验 | 已保存指定发送方、接收方、内容及业务版本，尚未通过接收校验 |
| 控制层已接收 | 当前业务版本、接收岗位/阶段、实际材料哈希及对应合约校验通过；不代表质量审核或人工批准 |
| 已退回补料 | 校验发现材料缺失，或分镜报告当前动作无法制作；原交付保留，另有指定范围补料单 |
| 补料已交回 | 新交付关联原请求且通过接收校验；仍须分镜和独立复审 |

记录另外显示实际模型调用及其提交证据，或明确显示缓存复用与原始调用编号。
缓存来源无法验证时保持未知；复用结果不冒充新调用。调用响应也不证明模型已正确理解或落实要求。

## 定向返修

启用既有的独立分镜配置 `creative.separate_storyboard=true` 后：

1. 编剧交付完整剧本。控制层对选定范围检查唯一镜头编号及非空动作。
2. 缺少动作时不调用分镜模型，生成分镜导演→编剧的补料单。分镜语义阻断也生成同类请求。
3. 在既有 `max_review_rounds` 内，将补料单、当前稿、独立审核意见和范围外保留镜头交给编剧。
4. 控制层只采用请求镜头的新内容，保留范围外镜头及原稿角色、剧名等设定；只重新分镜该范围，再交独立审稿。
5. 补料并不代替复审。超过既有轮数仍未通过时，沿用原人工决策入口，保存原稿、返修稿、补料单及审核意见。

未开启独立分镜的项目继续使用原创作方式，仍记录剧本→独立审核与通过审核后的视觉设计交接。
全剧规划记录设定→编剧、大纲→全剧审稿，以及审稿→策划/编剧的返修反馈；规划仍受既有 3 轮上限及人工确认约束。
不会自行更改模型分工、费用授权、审核分数、锁定成果或最终批准规则。

## 持久化与恢复

每个制作目录独立使用 `planning/handoffs.sqlite3`。交接编号由项目、业务版本、岗位/阶段、合约、范围、冻结内容及来源哈希、批准依据、关联补料单决定。
同一交付重复提交或接收不会重复建单；实际调用和缓存复用事件去重。
项目修订/进度刷新不等于业务输入变化；剧本/规划/制作等业务代数变化后，旧交接不能接收为当前稿。

交付正文、批准依据和补料要求保留各自的版本及哈希，读取时校验；不将当前版本倒填到历史内容上。
接入现有执行上下文时，沿用实时暂停、任务介入及锁定检查。
分镜退回时保留已经完成的局部分镜结果；恢复同一尝试时重放此结果并复用正常调用缓存，避免丢失其他镜头或重复调用。
这不替代队列租约、任务状态和原调用回执，也不扩展为通用的多代理自主调度。

## 只读 API

- `GET /api/factory/projects/{project_id}/handoffs?offset=0&limit=30`：摘要、相关补料单、总数；`limit` 为 1–60。
- `GET /api/factory/projects/{project_id}/handoffs/{handoff_id}`：该交付冻结正文与批准依据。
- 工作流 `flow.controlled_handoffs` 包含首页摘要。常规轮询不读取全部正文。

沿用现有 Host/Origin 和项目路径边界，只提供 GET；模型或页面无法通过这个接口创建请求、修改交接、扩大镜头范围或批准成果。

## 验证边界

自动验证覆盖缺失动作→定向补料→复审、语义退回恢复、范围外内容保留、版本隔离、批准与结构校验、已有锁定/暂停、持久化幂等、调用和缓存来源关联、真实本机 HTTP、界面按需阅读及明暗/桌面/手机画布稳定性。
模型输出使用离线 fixtures 或本机模拟传输；这些检查不评价真实模型的创作质量。
