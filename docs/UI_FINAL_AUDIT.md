# 全站 UI 自查：内容对齐、弹窗边界及错误可见性

继续关联 #51 / PR #52，比较基线仍为 #50。此次增量从 `823ae9f` 开始，仅更新PR，不部署服务器。正式服务保留此前集成提交 `cfc82e0`；后端API、模型配置、任务、审核和生产数据不变。

## 确认的问题及修复

| 问题 | 修复与验收方式 |
| --- | --- |
| 项目操作外框同高，文字仍上偏7.5px并带原生三角 | 使用统一按钮排版及16px Lucide下拉图标，文字和SVG按实际Range中心线验证，支持原生Enter/Space、Esc、失焦及点击外部关闭。 |
| 禁用下载下方的说明撑高操作区 | 原因归入项目摘要行，保持唯一`aria-describedby`关联，有无成片的操作控件均44px，说明仍可见。 |
| 320px业务控件换行后，菜单相对按钮右对齐而裁掉左半边 | 菜单相对整个操作区定位；检查每个菜单项的完整矩形与实际点击中心命中。 |
| 费用页无错误时也空出约84px | 移除页面级空错误占位，提交或读取失败进入共享浮层；授权与账单的字段校验及输入保持不变。 |
| 新建弹窗保存/取消在844px高视口被裁3–4px | 共用底栏贴可视区底部，保留底部安全间距；逐个检查按钮完全处于弹窗可见范围。 |
| 服务详情抽屉左偏15px，管理按钮拆字 | 修正抽屉边界，正文独立滚动、标题不移动，管理操作不压缩拆字。 |
| 根稳定滚动条轨道裁掉全宽抽屉及右侧焦点环 | 共享滚动锁在开放弹窗时取消根预留轨道，以等量body内边距保留原内容宽度；同时考虑Chromium的实际根布局宽度，支持嵌套及不同释放顺序。 |
| 服务保存失败时消息藏在底栏后或视口外 | 弹窗保留错误槽，错误出现时将其滚入视野，不移动焦点、不打开详情；保留输入，完整信息仍可展开。 |
| 很长项目名在手机占十余行 | 页头最多显示两行，完整名称保留在标题提示与可访问名称中；导航和工具与标题首行对齐。 |

全局：总览、项目、素材库、待办、模型与连接、制作流程与团队、运行记录。项目：概览、待办决策、团队、镜头、剧本、质检、交付、系列资产、素材定稿、任务费用。对320、390、768、1024、1440、1920及浅深主题实际查看，覆盖空数据、待人工处理、生成中、失败和交付场景。

另检查服务添加/编辑、服务详情、项目状态、新建制作、项目操作等7类弹窗/菜单的84种组合；长标题与503长错误压力场景；31模型列表滚动、真实键盘焦点环、嵌套错误详情逐层关闭、移动导航转新建弹窗、草稿、旧链接、版本、证据和下载。没有使用测试数量替代实际截图和命中检查。
